WHAT CHANGED vs v11
-------------------
Control-register bits 24:22 (dsp_flush_sel) and 27:25 (dsp_accum_sel)
select the DSP chain's per-step counts at runtime, and read back:

    sel   FLUSH_N (settle discard)   ACCUM_N (samples summed)
     0        1088 = the generic          2400 = the generic
     1         768                        2000
     2         512                        1600
     3         384                        1200
     4         256                        1000
     5         192                         800
     6         128                         600
     7          64                         400

    seq_adder.vhd       flush_count / accum_count input ports; the generics
                        stay as defaults and size the counter; a registered
                        "last index" per phase replaces the constant compare.
    rx.vhd              DSP_FLUSH_TABLE / DSP_ACCUM_TABLE, dsp_pick() (entry
                        0 = the generic, others clamped to it), one
                        synchroniser per select bit into rx_clock, one
                        registered lookup feeding both accumulators.
    bladerf-hosted.vhd  wires nios_gpo_slv(27:22) to rx; readback of the same
                        bits in gpi_readback (as v10 did for bit 6).

Per-step need = FLUSH_N + ACCUM_N. The dwell must exceed it by the Nios
restart jitter; v11 ran 3488 at dwell 4096 (608 of guard) without a miss.
Change the selects only between sweeps (the FPGA samples them continuously;
a change mid-step corrupts that step). The host applies them before EXEC.

Simulation (ModelSim 2020.1, rx_dsp_onoff_tb):
    sim_dsp_sel.do     generics 1088/2400, selects 2/2 -> results after
                       2112 samples/step, 5 ratios within 3 LSB       PASS
    sim_dsp_on / off / resync                                         PASS
    (the testbench's reference model now mixes by the tone before summing;
     the old raw sum was exactly zero over 16 whole cycles.)

WHAT TO MEASURE FIRST
---------------------
    FLUSH 512 is an assumption. On this image, with the services up and the
    sweep stopped:
        python3 radar/benchmark_sweep.py --mode dsp --dwell 3456 --flush 0 --accum 2 --sweeps 1200 --label f1088
        python3 radar/benchmark_sweep.py --mode dsp --dwell 3456 --flush 1 --accum 2 --sweeps 1200 --label f768
        python3 radar/benchmark_sweep.py --mode dsp --dwell 3456 --flush 2 --accum 2 --sweeps 1200 --label f512
        python3 radar/benchmark_sweep.py --mode dsp --dwell 3456 --flush 3 --accum 2 --sweeps 1200 --label f384
    S_repeat vs flush says where the AD9361 has settled. Pick the smallest
    flush whose S_repeat matches f1088 within the control spread, and put it
    in DSP_DEFAULT_FLUSH_SEL. Then the same for --dwell 3456 vs 3200 vs 3072
    (the Nios rail) to find the fastest stable step.

HOW TO USE
----------
    Pi, services stopped, on the v12-chain-select checkout:
      bladeRF-cli -l .../fpga/images/hostedxA9_niosIIf_sweep_dsp_v12_signaltap.rbf
      python3 radar/check_bit6.py        -> HOST, bit 6 reads back
    then start.py, set_sweep_mode.py dsp, and look for
      [sfcw] DSP chain: FLUSH 512 + ACCUM 1600 = 2112 samples/step; dwell 3456 leaves 1344 of guard
    on the console. On v11 the same line ends "(image has no runtime select)"
    and reports 1088 + 2400.
