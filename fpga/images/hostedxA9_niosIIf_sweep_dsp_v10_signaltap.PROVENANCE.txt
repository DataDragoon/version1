WHAT CHANGED vs v9 -- the config-GPIO readback of bit 6
--------------------------------------------------------
Root cause found in code, 2026-09-11:

  bladerf_config_gpio_read() returned pack(nios_gpio.i, '0')
  (bladerf-hosted.vhd, Nios gpio_in_port). pack(nios_gpi_t) in bladerf_p.vhd
  copies only the NAMED nios_gpo_t fields (usb_speed, rx_mux_sel, packet_en,
  ...). Bit 6 -- dsp_path_en -- is not a named field; it is tapped raw from
  nios_gpo_slv(6) for U_sync_dsp_path_en. So the readback word had bit 6 =
  'U' and the host always read it as 0, whatever had been written.

  libbladeRF does read-modify-write on this register: perform_format_config()
  (every sync_config), bladerf_set_pll_enable(), clock select, ... Each of
  those read bit 6 as 0 and wrote it back as 0. Any such call after
  dsp_path_enable(True) silently deselected the DSP FIFO, and the FX3 went
  back to draining the stock sample FIFO -- raw samples at the Nios sweep
  rate, which is exactly the symptom observed on the Pi.

The fix (bladerf-hosted.vhd):

    signal nios_gpi_slv : std_logic_vector(31 downto 0);
    ...
    gpi_readback : process(all)
        variable v : std_logic_vector(31 downto 0);
    begin
        v    := pack(nios_gpio.i, '0');
        v(6) := nios_gpo_slv(6);      -- dsp_path_en now reads back
        nios_gpi_slv <= v;
    end process;
    ...
    gpio_in_port => nios_gpi_slv,     -- was pack(nios_gpio.i, '0')

Effect: bladerf_config_gpio_read() returns the true state of bit 6, so every
libbladeRF read-modify-write preserves it, and the Pi driver's
"config_gpio=0x..." print will show 0x40 set while the DSP path is selected.
The host-side ordering in version1 commit aafe1c5 (write bit 6 last,
re-assert on a raw buffer) remains as a second line of defence.

Host-side counterpart: version1/pi/radar/bladerf_driver.py @ aafe1c5+,
test: python3 radar/test_dsp_path.py.

HOW TO USE
----------
    Pi:    bladeRF-cli -l hostedxA9_niosIIf_sweep_dsp_v10_signaltap.rbf
           (services restarted from the version1 tree, then
            python3 radar/set_sweep_mode.py dsp / python3 radar/test_dsp_path.py)

    Expect on the sdr_server console:
           [bladerf] DSP result path selected, sample mode (config_gpio=0x....4.)
                                                                           ^ bit 6
    and test_dsp_path.py: RESULT: PASS with sweep_core='dsp'.

    If the driver still reports "buffer is raw samples ... bit 6 is not in
    effect" on THIS image, the write itself is not arriving (host -> FX3 ->
    Nios); the readback now makes that visible: read config_gpio straight
    after dsp_path_enable(True) and bit 6 will be 0.
