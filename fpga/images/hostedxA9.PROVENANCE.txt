WHY THIS IMAGE IS NOT TRUSTWORTHY
---------------------------------
Timing Analyzer, Slow 1100mV models, setup:

    AD9361 rx clock (pll_sclk divclk)   85C : -0.310 ns
    AD9361 rx clock (pll_sclk divclk)    0C : -0.828 ns

rx_clock is an alias of ad9361.clock, so complex_div, both seq_adders and the
DSP FIFO write side all sit in the failing domain. That same clock closed at
+0.096 ns on 2026-09-05 with none of this logic present, so the DSP chain cost
roughly 0.4 ns in the one domain with no margin.

An image that fails setup still loads and often appears to work. The symptom is
intermittent, temperature-dependent corruption on the sample capture path --
worse cold (-0.828) than hot -- which reads as an RF problem rather than a
timing one. Do not trust measurements taken with this image.

The failure is combinational depth, not capacity (6% of the device is used), so
the fix is pipelining, not rearchitecting.

altera_reserved_tck is +5.083 ns here, up from -3.608 ns on 2026-09-05. That
earlier failure was SignalTap loading the JTAG hub, not a design problem; this
build has no SignalTap.

KNOWN GAP: DELIVERY TO THE HOST
-------------------------------
Separately from timing, the DSP path does not yet stream to the host.
fx3_gpif.vhd:270-273 sets its burst threshold as:

    packet_enable = '1'  ->  rx_meta_fifo_empty = '0'
    packet_enable = '0'  ->  (rx_fifo_full & rx_fifo_usedw) >= gpif_buf_size

The DSP route bypasses fifo_writer, so nothing writes the meta FIFO and packet
mode never bursts. In non-packet mode gpif_buf_size is 2048 while the DSP FIFO
holds at most 51 words (102 read-side); the concatenated full flag satisfies the
comparison anyway, and fx3_gpif has no underflow check during a burst
(rx_fifo_empty is an input port but is never referenced in the state machine),
so it would over-read by ~1946 words.

Fixing this needs either meta-FIFO writes on the DSP path or the results routed
back through fifo_writer's packet port.
